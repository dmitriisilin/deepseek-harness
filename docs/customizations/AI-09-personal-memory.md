# AI-09 — Личная память

Статус — испытана на красном. Для зелёного готовятся сборка, изолированная проверка и начальный контекст из истории. Семейная память вне этой фичи.

## Решение

Оба движка запущены локально. Honcho и Hindsight получают один завершённый обмен и обрабатывают его на DeepSeek Flash с отдельными ключами. В тестовом режиме Honcho возвращает краткий личный профиль из кэша и предоставляет модели инструмент поиска. Hindsight сохраняет обмены и обрабатывает их в своём банке. Источник чтения выбирается в конфигурации профиля. Поиск вызывается моделью по необходимости. Чат «Без памяти» пропускает подстановку профиля, поиск и запись.

Профили Димы и Кати изолированы. Для зелёного предусмотрены отдельные пространства и банки с собственными именами. Источник чтения на первом зелёном выпуске — Honcho. Схема хуков, закреплённые версии адаптеров и базовый замер находятся в [папке интеграции](memory/README.md).

## Карта коммитов

| Коммит | Содержание |
| --- | --- |
| `e4dfbc7ede` | Подключение двух адаптеров, сервис, настройки красных профилей, исходный вход в чат без памяти |
| `c44a8c2c72` | Выбор памяти на экране нового чата, расширение загрузки изолированных клиентских модулей |
| `d8b2ad4115` | Оформление переключателя и меню |
| `e104c7427b` | Базовый замер расходов по ключам |
| `d4b9fa04b0` | Голосовая очередь и опережающая расшифровка. Самостоятельная правка в диапазоне выпуска |

Совместимость с апстримом проверяем на хуках создания агента, подготовки запроса и завершения хода, а также на пресете сессии и загрузке клиентских модулей. Замена форков допустима после проверки двойной записи, единственного источника чтения, изоляции владельцев и режима без памяти.

## Начальный контекст

Зелёная история остаётся в собственных профилях. Для начального контекста отбираем короткие сведения, прямо подтверждённые пользовательским сообщением. Каждой записи сопоставляем владельца, сессию и позицию в журнале. Разовые запросы могут подсказать тему поиска. Предпочтения, намерения и результаты работы имеют разный статус и не выводятся из предположений ассистента.

Готовые выжимки лежат локально отдельно для каждого владельца. Перед импортом их проверяем на актуальность, принадлежность и пригодность к использованию. Уже одобренный набор загружаем в обе системы от имени соответствующего профиля с воспроизводимыми идентификаторами записей. Сохраняем происхождение отдельно от текста, чтобы при повторе проверить дубль и при необходимости убрать импорт целиком. Тексты инструментов, вложения и секреты исключаем. Существующие красные банки сохраняем для сравнения.

## Готовность зелёного выпуска

1. Собрать кандидат из чистого коммита `di735` в отдельном каталоге с зелёным брендингом. Незакоммиченные эксперименты Supervisor и auto-review держать вне сборки. Зафиксировать входящие изменения, включая голосовую очередь, если берём весь диапазон.
2. Проверить кандидат в изолированных профилях обоих владельцев. Пройти обычный чат, голос, двойную запись, чтение Honcho, приватный режим и проверку отсутствия чужой записи. Проверить импорт сначала на тестовых пространствах и банках, в том числе повторный запуск.
3. Проверить запуск чата при недоступности каждого движка. Зависимость юнитов красного стенда требует локальный сервис памяти. Перед зелёным выпуском определить и проверить, как чат запускается при недоступности этого сервиса.
4. Сохранить прежний выпуск и конфигурацию юнитов. Для отката вернуть их, сохранив каталоги истории. Начальный импорт, активация памяти и переключение зелёного выполняются после отдельной команды.

Для общего порядка выпуска см. [AI Control release](AI-Control-release.md).
