# Личная память AI Control

Личная память включена на красном стенде для Димы и Кати. Проверки ниже использовали отдельные синтетические банки.

## Локальные сервисы

`bash dsh/memory/start-local.sh` запускает Honcho, Hindsight и общий сервис эмбеддингов через rootless Podman. Honcho доступен на `127.0.0.1:18080`, Hindsight на `127.0.0.1:18888`. PostgreSQL, Redis и эмбеддинги доступны контейнерам через внутреннюю сеть Podman. Данные хранятся в именованных томах. Ключи `DEEP_SEEK_Honcho` и `DEEP_SEEK_Hindsight` читаются из `~/api.keys`. Текст, необходимый для генерации воспоминаний, обрабатывает API DeepSeek. Базы и вычисление эмбеддингов локальные.

## Контракт адаптеров

- Красные процессы Димы и Кати уже имеют отдельные профили. Привязываем их к личному пространству Honcho и личному банку Hindsight на сервере, независимо от рабочей директории. Схема инструментов не принимает идентификатор пользователя или банка.
- Honcho сохраняет штатный сбор сообщений. Hindsight в нашем форке начинает инициализацию на `agent/created`; завершённый обмен доступен на `agent/turn-stopping`. Перед фоновой записью снимаем копию обмена, чтобы она не зависела от срока жизни агента.
- В `agent/pre-step` активный провайдер даёт готовый короткий профиль. На холодном кэше профиль подгружается асинхронно. Явный инструмент поиска доступен только для активного провайдера. Автоматический поиск по текущему вопросу и заполнение памяти из git отключаем.
- Оба провайдера получают пользовательский текст и итоговый текст ассистента. Голосовой ход сохраняется как расшифровка. Вложения, внутренний контекст, промежуточные результаты инструментов и данные чужого профиля не входят в запись.
- У чата без памяти отключены все три пути: профиль, чтение инструментом и запись в оба провайдера.

## Проверка красного стенда

1. В голосовом чате без проекта первый запрос содержит расшифровку и один профиль активного провайдера.
2. Один завершённый обмен сохраняется в обеих системах. Повторная доставка того же хода не добавляет дубликатов.
3. Поиск возвращает данные только выбранного провайдера и текущего пользователя. Синтетическая запись Кати недоступна в чате Димы и наоборот.
4. Чат без памяти не читает и не пишет в обе системы. Отключение одного провайдера не прерывает ответ модели и запись во второй.

### Проверено на ноутбуке

Оба API вернули HTTP 200 на `/health`. Отдельные ключи DeepSeek вернули каталог с `deepseek-flash`. Синтетическое русское сообщение сохранилось и прочиталось в Honcho, а Hindsight вернул его по смысловому запросу.

При запуске нужны `podman`, `uidmap`, `fuse-overlayfs`, `passt` и `aardvark-dns`. Образы сервисов закреплены в скрипте. Для новой базы Honcho при первой инициализации его штатная утилита меняет размерность pgvector на 384. Существующая база с другой размерностью требует отдельной миграции.

Проверяемые адаптеры закреплены на Honcho DSH `22c6df79c2d95ced6a92f4a4b5c4ed6d2052eca5` и Hindsight `c828c7e41527d0c4916cac0ba2b56334fed4a79d`. В `patches/` сохранены исправления совместимости с текущим DSH. Honcho читает снимок журнала живой сессии, поскольку штатный запрос истории не нашёл синтетический быстрый чат. У Hindsight подписка на инициализацию переведена на `agent/created`, а 18 тестов адаптера прошли. Патчи также добавляют личный режим, который разделяет запись и выбор источника чтения.

Совместный smoke-test на копии staging-профиля прошёл через настоящий веб-чат DSH. Flash завершил один синтетический ход без инструментов. Honcho нашёл исходный пользовательский текст и ответ, Hindsight нашёл сохранённый факт о цвете тестового маяка. Это проверка записи через хуки.

Личный режим адаптеров включается переменной `AI_CONTROL_MEMORY_PERSONAL=1`. `AI_CONTROL_MEMORY_READER=honcho` или `hindsight` выбирает единственный источник профиля и инструмента `personal_memory_search`; второй адаптер сохраняет обмен. Профили обновляются в фоне и ограничены 1200 символами. Hindsight читает краткий документ `personal-profile` из своего банка; Honcho читает карточку своего пользователя. Для отключённого чата оба адаптера проверяют серверный пресет `memory-off`, который назначает переключатель на экране нового чата.

В двух изолированных прогонах Flash вызвал один и тот же инструмент при каждом выборе провайдера. Honcho вернул сообщение предыдущего хода. Hindsight выполнил вызов, но не нашёл запись сразу вслед за асинхронной записью. После индексации повторный вызов инструмента из DSH вернул сохранённый факт.

## Красные профили

Красный профиль Димы использует пространство Honcho и банк Hindsight `ai-control-red-dima`. Катя использует `ai-control-red-kate`. Выбор источника задаёт `AI_CONTROL_MEMORY_READER` в файле `personal-memory/systemd.env` соответствующего профиля. После изменения источника перезапускается только этот красный сервис. По умолчанию у обоих источником чтения служит Honcho.

Переключатель «Без памяти» на экране нового чата открывает пустую сессию с сохранённым пресетом `memory-off`. Пресет отключает профиль, инструмент и запись. Память обычных чатов начинает накапливаться с момента включения. При пустом кэше первый запрос отправляется сразу, а профиль загружается в фоне. Hindsight обновляет документ профиля по часовому расписанию, если в банк поступили новые воспоминания.

Фронтенд и клиентские модули красного стенда собираются в отдельный каталог выпуска. `AI_CONTROL_WEB_DIST` и `AI_CONTROL_MEMORY_CLIENT_PLUGINS` задаются только в окружении красных сервисов. Локальные контейнеры памяти поднимает пользовательский `ai-control-memory.service`, который нужен обоим красным сервисам.

## Базовый замер расхода

Снимок [DeepSeek Usage](https://platform.deepseek.com/usage) на 28 ноября 2026 года. Период в кабинете — последние 30 дней, часовой пояс GMT+7.

| Ключ | Запросы | Токены | Расход по кабинету |
| --- | ---: | ---: | ---: |
| Honcho | 44 | 81 401 | $0,02 |
| Hindsight | 77 | 393 998 | $0,02 |
| Оба ключа | 121 | 475 399 | $0,05 |

Кабинет округляет каждую сумму отдельно. Снимок включает подготовительные прогоны и фоновую обработку, поэтому подходит как стартовая точка для учёта, а разница между строками отражает разную нагрузку. На момент замера оба движка получают новые диалоги красных профилей, источником чтения служит Honcho.

Для сравнения записываем один и тот же набор завершённых обменов в обе системы и сверяем расход по отдельным ключам за общее фиксированное окно. Снимаем исходные счётчики перед прогоном и итоговые после завершения фоновых операций обеих систем. Записываем число обменов, запросы, токены и списания. Замеры чтения проводим отдельно с одинаковыми вопросами к каждому движку, чтобы обращения рабочего чата к Honcho не смешивались со сравнением затрат на запись.

## Проверки перед включением

В браузерном тесте кнопка создала сессию с сохранённым пресетом `memory-off`. Заголовок запроса исключил `personal_memory_search`, а контрольная фраза отсутствовала в поиске обеих баз. В двух синтетических банках каждого движка поиск вернул свою запись и не вернул запись другого пользователя.

В обоих режимах чтения прогретый профиль и расшифровка пришли вместе в первый запрос DSH. Расшифровка записалась в обе системы, а тестовый профиль Honcho в захват не попал. Голосовой тест использовал браузерную WAV-загрузку и локальную заглушку распознавания. Штатный Deepgram принял синтезированный WAV, но вернул пустую строку, поэтому качество его распознавания этим прогоном не подтверждено.

Отдельно браузер открыл оба рабочих красных профиля после перезапуска и показал кнопку «Чат без памяти». Основной процесс DSH и оба зелёных процесса сохранили свои PID.
